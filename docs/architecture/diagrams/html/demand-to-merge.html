AIPe · Arquitetura · Demanda → Merge

Demanda → Merge

grafo 12 nós · 14 arestas

Uma demanda vira PRs mescladas por um caminho obrigatório — decompor → despachar um especialista para uma worktree isolada → o especialista abre a PR → um gate de QA independente → merge. O coordenador nunca edita um repo: suas únicas ações são decompor, despachar, investigar read-only e escalar. O dispatch é gated numa spec aprovada pelo PE, e o QA julga o diff, não o relato do autor.

Kinds neste diagramadeterministic · CLI testadajudgment · prosa de SKILL.mdgate · decisão humanastructure · substrato
Nós — nota & evidência
1Demanda do PEstructure

Um bug, feature ou task cobrindo um ou mais repos. Trabalho que muda repos sempre flui por dispatch — nunca inline.

evidência skills/operate/SKILL.md:26
2Abre uma jornada (ledger)deterministic

Uma demanda = uma jornada; vários especialistas podem rodar sob ela. O id da jornada chaveia todo comando e toda linha do ledger.

evidência skills/operate/SKILL.md:183
3Decompõe em tasks por pacotejudgment

A unidade de trabalho é um pacote, não o repo: um repo flat é um pacote implícito (fqid = nome do repo); um monorepo tem um pacote por serviço (fqid = repo/pacote). Pacotes distintos rodam em paralelo; a lei serializa só o MESMO pacote.

evidência skills/operate/SKILL.md:190
4Sequencia com o grafo de relaçõesjudgment

Se a task do repo A depende de um contrato que o repo B deve mudar antes, a task de B vai numa onda anterior. Um consumidor não pode shipar antes do seu produtor pousar — o verify do ledger sinaliza exatamente isso.

evidência skills/operate/SKILL.md:199
5Spec aprovada pelo PE (approved=true)gate

O dispatch é gated na aprovação da Orientation Spec pelo PE. Até aprovada, o coordenador espera ou emenda — não despacha. A aprovação é uma flag registrada na spec da jornada.

evidência src/journey/types.ts:138
6Despacha um especialista (nunca inline)deterministic

O coordenador NUNCA edita um repo. Suas únicas ações são decompor, despachar, investigar read-only, escalar. Uma tabela de não-exceções proíbe "é simples / urgente / uma linha / eu sei o fix" — só uma instrução humana explícita sobrepõe.

evidência skills/operate/SKILL.md:26
7Worktree isolada + claim de pathdeterministic

Cada especialista trabalha na sua própria worktree git, no seu próprio branch, nunca tocando o checkout primário. Dois especialistas coexistem num repo só quando seus paths declarados são disjuntos (veja o diagrama concurrency-model).

evidência CONTRIBUTING.md:32
8Especialista trabalha test-first, abre PRdeterministic

O especialista abre a PR — nunca o coordenador. Uma mudança de comportamento sem teste não é revisável aqui; a entrega registra evidência (os comandos rodados e o que a saída mostrou).

evidência CONTRIBUTING.md:39
9Gate de QA independentejudgment

Toda entrega é revisada por uma persona de QA independente contra o diff e os critérios de aceite — não o relato do próprio autor. Aprova → verified; reprova → failed e volta a uma task de conserto (veja o diagrama rework-loop).

evidência CONTRIBUTING.md:36
10Escala cross-repo para o PEgate

Uma necessidade cross-repo que o especialista não deve tocar é escalada: o PE decide o escopo. Distinta de blocked (uma resposta que o coordenador pode dar).

evidência skills/operate/SKILL.md:156
11PR mesclada em devdeterministic

Trabalho verificado mescla em dev e a unidade é registrada merged (imutável). Isto é integração, NÃO produção — o diagrama merge-to-production mostra os dois passos além dele.

evidência skills/operate/SKILL.md:158
12Oferta de promoção (→ merge-to-production)gate

Com trabalho verificado em dev, o coordenador oferece a promoção ao PE — nunca promovendo por conta própria. A continuação é o diagrama merge-to-production.
