Harness containment

graph 12 nodes · 13 edges

Session-mode dispatch is non-interactive by construction, so a harness is eligible only if a block-before-execute hook can be TRUSTED with no human present. At RUNTIME that question is binary — containmentHook() is null or it is not — and only the four adapter-backed harnesses ever reach dispatch. But the product records a WIDER knowledge in a three-state ledger over the ten harnesses agentop can host: containable-proven, non-containable-proven, and unestablished. The third state exists because "no adapter yet" and "cannot be contained without a human" had collapsed into one misleading "coming soon" — the exact signal the PE flagged for Antigravity. The binding refusal is still re-run at the moment a session actually starts, not just as advice.

AIPe · Arquitetura · Contenção de harness

Contenção de harness

grafo 12 nós · 13 arestas

Dispatch em modo sessão é não-interativo por construção, então um harness só é elegível se um hook block-before-execute puder ser CONFIÁVEL sem humano presente. No RUNTIME essa pergunta é binária — containmentHook() é null ou não é — e só os quatro harnesses com adapter chegam ao dispatch. Mas o produto registra um conhecimento MAIS AMPLO num ledger de três estados sobre os dez harnesses que o agentop pode hospedar: containable-proven, non-containable-proven e unestablished. O terceiro estado existe porque "sem adapter ainda" e "não pode ser contido sem humano" haviam colapsado num único "coming soon" enganoso — o exato sinal que o PE sinalizou para o Antigravity. A recusa vinculante ainda é reexecutada no instante em que uma sessão de fato começa, não só como conselho.

3Ledger de contenção — três estados, dez harnessesstructure

Além da regra binária de runtime, o aipe registra, para CADA harness que o agentop pode hospedar, se existe algum hook de interceptação não-interativo confiável. A resposta é mantida em TRÊS estados, não dois — containable-proven, non-containable-proven, unestablished — como um ledger de dados que o resto do aipe lê (containmentFor / harnessesInState). NÃO muda a união de dispatch nem a regra de elegibilidade; as quatro linhas com adapter são travadas em isContainable(getAdapter(id)) pelo compat.test.ts, então este arquivo não pode derivar do comportamento do código. Toda linha "proven" cita uma fonte PRIMÁRIA (a doc do próprio tool) com a data em que foi lida.

9…mas nunca CONFIADO ⇒ null de propósitodenied

O Codex só carrega o hook não-gerenciado de um projeto depois que um humano o CONFIA interativamente via `/hooks` — a confiança é por hash, sem jeito de autodeclarar em arquivo de config. Dispatch não-interativo não vence esse gate, então containmentHook() devolve null de propósito: silenciosamente errado (um hook que não bloqueia nada) é pior que inelegível.

10Copilot — directory trust default-ONdenied

Um mecanismo DIFERENTE, mesmo desfecho: o Copilot CLI pede ao usuário para confirmar confiança em qualquer diretório que ele não viu antes, default-ON. Uma worktree é por construção nova — ausente do registro de confiança do CLI — então sempre bate no prompt. O escape global trustedFolders sobreviveria à worktree e seu efeito no carregamento de hooks é não-confirmado, então containmentHook() devolve null.
