Concurrency model

state machine 13 nodes · 13 edges

Concurrency in AIPe is a strict progression, not three loose features: an atomic filesystem claim makes the dispatch law physics, identity-per-task lets non-writing roles run in parallel, and the lock granularity descends from repo to path — with a reconciler that survives declared paths aging.

1Atomic claim (link = O_CREAT|O_EXCL)deterministic

The claim is a hard link of a temp file onto the lock path: link() is atomic and fails EEXIST if the lock exists, so the winner's lock is always fully written — no empty-file window. The law stopped being a suggestion and became a filesystem invariant.

3isLockActive — four signalsdeterministic

Death is decided, never assumed. (1) a provably-dead pid (kill(pid,0) → ESRCH) is the only positive proof of death; (2) a dispatched/redirected ledger entry is durable proof of life; (3) a freshly-created lock is granted a grace window to close the claim→record gap; (4) an unverifiable owner (pid ≤ 0) is treated ALIVE — never a silent orphan.

Modelo de concorrência

máquina de estados 13 nós · 13 arestas

Concorrência no AIPe é uma progressão estrita, não três features soltas: um claim atômico de filesystem torna a lei de dispatch física, a identidade por task deixa papéis que não escrevem rodarem em paralelo, e a granularidade da trava desce de repo para path — com um reconciliador que sobrevive ao envelhecimento dos paths declarados.

Nós — nota & evidência
1Claim atômico (link = O_CREAT|O_EXCL)deterministic

O claim é um hard link de um arquivo temporário sobre o path da trava: link() é atômico e falha EEXIST se a trava existe, então a trava do vencedor está sempre totalmente escrita — sem janela de arquivo vazio. A lei deixou de ser sugestão e virou invariante de filesystem.

evidência src/dispatch/lock.ts:248
2EEXIST → outro já temdenied

Um claimant perdedor vê EEXIST e não retenta às cegas — inspeciona o dono atual quanto a vida antes de decidir colisão vs takeover.

evidência src/dispatch/lock.ts:256
3isLockActive — quatro sinaisdeterministic

A morte é decidida, nunca presumida. (1) um pid provadamente morto (kill(pid,0) → ESRCH) é a única prova positiva de morte; (2) uma entrada dispatched/redirected no ledger é prova durável de vida; (3) uma trava recém-criada ganha janela de graça para fechar o gap claim→record; (4) um dono não-verificável (pid ≤ 0) é tratado como VIVO — nunca órfão silencioso.

evidência src/dispatch/lock.ts:148
4Reconcilia órfão → retenta claimdeterministic

Uma trava obsoleta (pid morto, sem entrada viva no ledger, fora da graça) é removida e o create atômico é retentado. Recuperação comum não exige outorga do PE.

evidência src/dispatch/lock.ts:283
5--force sobre trava VIVAgate

Sobrepor uma trava viva é decisão humana registrada, não atalho do agente: --force é recusado (unauthorized-force) a menos que a jornada carregue uma autorização forceClaim do PE para aquela unidade.

evidência src/dispatch/lock.ts:269
6Identidade = Persona · taskdeterministic

A unidade endereçável ganhou um eixo de task: a chave da trava incorpora a task, então uma persona reivindicando duas tasks distintas numa unidade produz dois arquivos de trava independentes.

evidência src/dispatch/lock.ts:40
7predicado escreve / não-escrevedeterministic

Concorrência de um papel deriva do comportamento, não de uma lista de nomes: roleWritesToRepo retorna false só para NON_WRITING_ROLES (qa); um papel desconhecido cai em escreve ⇒ serializa (falha segura).

evidência src/dispatch/roles.ts:21
8Lei: qualquer escritor ⇒ serializadeterministic

validateBatch admite N dispatches não-escritores numa unidade só se cada um carrega uma --task distinta; no instante em que qualquer membro escreve, as duplicatas serializam (rejeições same-repo / same-package).

9Path-lock: paths disjuntos coexistemdeterministic

A trava desceu de repo para path. Dois escritores num repo coexistem sse seus conjuntos de paths declarados são disjuntos; sobreposição serializa. Conjunto vazio significa WHOLE (**) e sobrepõe tudo (trava de repo retrocompatível).

evidência src/dispatch/lock.ts:455
10Mutex de guarda por unidadestructure

Scan→decide→escreve sobre o conjunto de sobreposição é serializado entre processos por uma guarda por unidade construída no mesmo primitivo atômico de link, com TTL para que um dono travado não trave a unidade.

evidência src/dispatch/lock.ts:348
11Paths declarados ENVELHECEMstructure

A falha não-óbvia: um conjunto de paths declarado se afasta da realidade. Evidência de campo — o escopo de um dev cresceu de 2→16 arquivos por razão legítima; o `bun install` de outro mexeu em ponteiros de submódulo que ele nunca quis tocar.

evidência src/dispatch/detect.ts:2
12Reconcilia contra o que o git tocoudeterministic

A trava é reconciliada contra o que o branch REALMENTE moveu — o diff commitado (base...HEAD) mais a árvore de trabalho (status --porcelain), com renames registrando os dois extremos — e revê a sobreposição no conjunto real. Drift que cresce até o path de um claim vivo aparece como colisão em vez de escrita dupla silenciosa.
